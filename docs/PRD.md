## 1. 一句话定位

**知映（zhiying）是一个把「收藏夹里吃灰的视频」变成「可检索、可问答、可溯源到时间点的视频知识库」的自动化系统**：输入视频链接（B站 / YouTube / 视频号 / 本地文件），自动完成下载 → 语音转写 → 画面识别 → 多模态文案对齐 → 结构化知识入库（切片向量化 + 主题摘要），最终支撑「提问即答、答必溯源到视频时间点」的使用体验。

**市场洞察**：长视频（深度访谈、教程、行业分享）时效性强、模型预训练未覆盖，但动辄数小时，用户「收藏=学过」是最普遍的知识管理失效场景。仓颉.Skill 在 GitHub 已 12K+ Star，验证了「视频内容结构化提取」需求真实存在；但其产出形态是面向 Agent 挂载的 Skill 包（RIA 方法论卡），面向的是「让 Agent 会做某类事」；**直接面向人的视频知识库（检索/问答/溯源）是它的空白**——这正是本项目的定位：参照其分析视频的管道方式，产出形态换成知识库。

## 2. 技术栈总结（基于文章与仓颉生态取证）

### 2.1 文章核心流水线（仓颉.Skill 3.0 + video-downloader + LongCat-2.5）

| 环节 | 工具/模型 | 关键细节（文章原文取证） |
|---|---|---|
| 视频下载 | yt-dlp + ffmpeg（video-downloader skill） | 默认 1080p；断点恢复；多级缓存；失败只重跑出错片段 |
| 平台扩展 | 视频号支持 | 首次微信扫码登录后保存授权状态，后续复用 |
| 语音转写 | 平台字幕优先（如 B站 AI 字幕，经 Cookie 获取）→ 硅基流动 SenseVoiceSmall（免费）→ 本地 Whisper（用户显式选择才用） | 三级降级策略 |
| 画面理解 | 多模态大模型（文章用美团 LongCat-2.5，1.6 万亿参数 MoE、原生多模态 RVQ、1M 上下文） | 视频经第三方站点转公网临时 URL 传入 API |
| 切片策略 | Agent 先分析完整文案 → 切重要片段交给 VLM，最长每 10 分钟一段，支持并发 | 「Agent 智能选段」模式 |
| 三种视觉模式 | 关键帧 / 完整视频 / Agent 智能选段 | 按内容类型选择 |
| 输出物 | multimodal_transcript.md | 含口播、画面事实、屏幕文字、动作、时间戳 |
| 蒸馏 | 仓颉.Skill（RIA-TV++ 七阶段管道：整体理解 → 5 并行抽取器 → 三重验证 → RIA++ 能力卡 → 卡片链接 → 压力测试 → 确定性编译） | 产出可挂载 Agent 的 Skill 包；3.0 起默认单 Skill 输出 |
| Agent 运行环境 | Codex / Claude Code / WorkBuddy 等编码 Agent | 蒸馏由 Agent 编排脚本完成，非传统后端服务 |
| 成本 | LongCat-2.5 百万 token 约 0.3 元；4.5h+30min+30min 三条视频合计 755 万 token | 官方赠送 1000 万 token，缓存命中不计费 |

### 2.2 实测性能参考（文章数据）

- 4.5 小时 B站长谈：video-downloader 处理约 30 分钟（1GB 源视频下载占大头），仓颉蒸馏约 50 分钟。
- 蒸馏产物可通过新对话挂载 Skill 直接问答，答案可标注来源视频时间段。

### 2.3 对本项目的选型启示

1. **Python 工具链是视频处理生态的母语**（yt-dlp / ffmpeg / SenseVoice / 关键帧检测均有成熟库），本项目核心管道采用 Python，与既有 Java 主栈项目相互独立。
2. **VLM 必须可插拔**：文章绑定 LongCat-2.5（截至发文 API 仅支持 URL 传视频，且「应该是即将开源」）；本项目将 VLM 抽象为适配器接口，LongCat-2.5 / Qwen-VL 系 / GLM-4V 均可配置切换。
3. **管道方式参考而非产出复用**：仓颉.Skill 与 video-downloader 验证过的管道方式（下载→字幕→选段→视觉识别→时间戳对齐）直接参照，其中工具链（yt-dlp/ffmpeg/SenseVoice）直接复用；但仓颉的产出形态（RIA 方法论 Skill 包）**不采用**——本项目产出面向人的知识库（检索/问答/溯源），不走方法论卡与 Agent 挂载路线。

## 3. 目标用户

| 用户群 | 核心诉求 | 使用形态 |
|---|---|---|
| 重度内容收藏者（首发用户=老板本人） | 把收藏的视频批量变成可问答的知识库 | 对话丢链接/V0.3 Web 界面发起任务，日常问答走知识库界面 |
| 知识工作者/研究者 | 按主题检索长视频内容，答案带时间戳可回跳验证 | 知识库检索 + 引用回跳 |

## 4. 用户旅程（即验收标准）

| # | 旅程 | 验收标准 |
|---|---|---|
| J1 | 处理一条视频 | V0.1 验收：提交一条 30 分钟 B站视频链接 → 任务完成 → 得到 multimodal_transcript.md（含结构化摘要）；V0.2 补齐：知识库条目入库 + 提问得到带时间戳引用的答案（知识库部分在 V0.1 阶段豁免） |
| J2 | 构建知识库 | 连续提交 ≥5 条同主题视频 → 知识库可按主题聚合检索，跨视频问答正确归属来源；每条视频自动产出主题摘要，无需任何手工整理动作 |
| J3 | 问答溯源 | 任一问答答案附带视频名+时间戳，点击可跳转原视频对应位置 |
| J4 | 失败恢复 | 任务中途断网/超时 → 重试后只重跑失败片段，不重复下载已完成的视频与已转写的音频 |
| J5 | 画面信息不丢失 | 对含 PPT 架构图/代码演示的视频问答时，答案能引用画面文字与图表内容（经 VLM 识别），而非只有口播 |

## 5. 功能需求

### 5.1 管道层（FR-1xx）

| 编号 | 功能 | 验收标准 |
|---|---|---|
| FR-101 | 视频接入：B站 / YouTube / 本地文件三类为 V0.1 必验收；视频号接入复用 video-downloader 的实现思路（MIT），不可行则降级延至 V0.2 | 三类必验收来源各完成 1 条真实视频端到端跑通；视频号 best effort；1080p 默认清晰度 |
| FR-102 | 下载引擎：断点恢复、多级缓存、失败片段级重跑 | 1GB 视频中断后重试不重新下载已完成部分 |
| FR-103 | 语音转写三级降级：平台字幕 → SenseVoiceSmall → 本地 Whisper（显式选择） | 无字幕视频自动落入第二级；三级均可产出带时间戳转写 |
| FR-104 | 画面识别三模式：关键帧 / 完整视频 / Agent 智能选段（≤10 分钟/段、并发） | 模式可配置；选段模式先分析全文案再切重要片段 |
| FR-105 | VLM 适配器：统一接口，首选 LongCat-2.5（DR-14 拍板；官方赠送 1000 万 token 活动，起步成本近零，文章实测效果好且便宜），Qwen-VL 系 / GLM-4V 为备选可配置。注意 LongCat-2.5 API 仅支持 URL 传图/视频，适配器内置 URL 桥接（本地帧图→临时公网地址） | 切换模型只改配置不改代码；适配器有契约测试；URL 桥接链路跑通（帧图→识别结果回收）；多模态识别质量抽检达标（含 PPT/代码画面） |
| FR-106 | 多模态文案产出：multimodal_transcript.md（口播+画面事实+屏幕文字+动作+时间戳） | 时间戳与原视频可对齐（抽查 3 处误差 ≤5 秒） |
| FR-107 | 结构化摘要：管道尾部用文本 LLM 对 multimodal transcript 产出视频级摘要 + 主题标签（入知识库，供聚合检索与浏览定位），配置化封装 LLM 分析提示词工程 | 每条视频入库时自动生成摘要与 ≥3 个主题标签；摘要内容可溯源到时间段 |

### 5.2 知识库层（FR-2xx）

| 编号 | 功能 | 验收标准 |
|---|---|---|
| FR-201 | 知识条目存储：原始转写、切片、摘要产物统一入库，PostgreSQL 统一存储（元数据+向量+全文同库） | 每条目可追溯到源视频、处理时间、模型版本 |
| FR-202 | 检索接口：pgvector 向量检索为主 + PG tsvector 全文为辅（中文分词在应用侧 jieba 预处理后写入 tsvector，不依赖 Windows 上难编译的中文分词扩展） | 同主题 5 条视频跨库检索，Top3 命中正确来源 |
| FR-203 | 增量更新：同视频重复提交不重复处理，内容变更可触发增量 | 重复提交秒级返回已有结果 |
| FR-204 | 问答服务：基于知识库的 RAG 问答，答案强制带来源引用；答案生成 LLM 默认与 VLM 同供应商（LongCat-2.5 文本能力，一个 Key 覆盖全部模型调用），适配器可切换 | 每个答案含视频名+时间戳；无据可答时明确说「知识库中无依据」 |

### 5.3 服务层（FR-3xx）

| 编号 | 功能 | 验收标准 |
|---|---|---|
| FR-301 | 任务队列：并发任务、状态查询、失败重跑 | ≥3 条长视频并发处理互不干扰；任务状态可查（排队/下载/转写/识别/摘要/完成/失败） |
| FR-302 | Web API：任务提交、进度、知识库检索、问答（FastAPI，决策记录 DR-8） | OpenAPI 文档完整；前后端联调通过 |
| FR-303 | Web 前端（Vue3）：任务管理台、知识库浏览、问答界面 | 覆盖 J1–J3 旅程操作路径 |
| FR-304 | 观测：任务级日志与耗时统计，各阶段 token/费用记录 | 每任务可查各阶段耗时与 token 消耗 |
| FR-305 | Agent 接入层：MCP Server 薄包装 REST API（§5.6），暴露 5 个工具供各 Agent 发现与调用 | OpenClaw / Claude Code / Codex 三端各完成一次真实「建任务+问答」调用 |
| FR-306 | 首次使用引导：安装/配置/第一条任务三步向导；未配置 Key 时阻断消耗命令并提示配置路径 | 新用户首次启动 5 分钟内完成第一条视频处理（从安装到产出 A1） |

### 5.4 最终构建产物规格（A1–A6）

| 产物 | 落地版本 | 结构定义 |
|---|---|---|
| A1 多模态文案 | V0.1（S6） | 双形态：`multimodal_transcript.md`（人读主产物：YAML front-matter 记 video_id/来源/时长/语言/管道版本；正文按 `[MM:SS]` 分段，每段标注 口播/画面事实/屏幕文字/动作）+ 伴随机器可读 `transcript.jsonl`（每行 `{start_ts, end_ts, speech, visual_facts[], screen_text[], frame_refs[]}`，为入库与向量化的结构源；两者由同一数据源生成，不允许手工分叉） |
| A2 知识条目（检索单元） | V0.2（S8/S10） | 表结构 V1 冻结于 S8：`videos`（源/状态/模型版本/耗时）→ `segments`（A1 JSONL 逐段落库）→ `chunks`（检索单元：相邻 segments 语义合并，目标 300–800 token，携带 video_id、[start_ts,end_ts]、模态标记）→ `chunks.embedding`（pgvector）；回答引用最小粒度=chunk 时间段；合并窗口与重叠率为可调配置 |
| A3 视频摘要与主题标签 | V0.1（S7） | `{summary_text, topics[], key_points[{claim, start_ts}]}`：视频级摘要 + ≥3 主题标签 + 可溯源要点清单；文本 LLM 基于 A1 生成，入知识库 videos 表供聚合浏览 |
| A4 问答产物 | V0.2（S11） | 结构化回答：`{answer_text, citations:[{video_id, title, start_ts, end_ts, quote}], note?}`；引用逐条对应 chunk 时间段可回跳；无据可答时 citations 为空并明确说明 |
| A5 导出型文档（预留） | 触发制（V1.0+，DR-16） | 整理型 md 文档（教程/笔记/讲义式）：文本 LLM 基于 A1/A2 重组+模板渲染；产物不回写知识库 |
| A6 Agent Skill 包（预留） | 触发制（V1.0+，DR-16/17/18） | 蒸馏任务包导出：导出器产出通用备料包（multimodal_transcript.md 副本 + 预填指令 README）；蒸馏执行器可插拔、知映不绑任何上游项目：用户可交给自己的任意编码 Agent（原生模型蒸馏/仓颉.Skill/其他蒸馏工具任选），仓颉仅为文档中的推荐选项之一，非必要条件 |

**导出器扩展机制（DR-16，DR-17 修正执行边界）**：A1（transcript.jsonl 结构源）与 A2（chunks）是所有产物的万能分叉点——新增任何产物形态（md 文档/Skill/srt 字幕/Anki 卡片/思维导图）都是管道末端的「导出器」后处理：统一输入 `{transcript, chunks, 摘要}`，输出文件，不触碰主管道、不回写知识库。**导出器必须是确定性函数**：纯 LLM+模板类产物（A5）可在导出器内完成；Agent 驱动型外部技能（如仓颉.Skill，需编码 Agent 会话执行 RIA-TV++ 七阶段，非可编程 API）只能走「备料模式」——导出器产出任务包+预填指令，由用户在自己的 Agent 中执行（与 DR-15 人审在环、DR-13 资源模型一致）。导出器按需注册（CLI `zhiying export <task_id> --format=xxx` / REST `POST /api/exports`），V0.1–V0.3 主管道不因预留而增加复杂度。

### 5.5 交互定义

**V0.1 CLI 命令面（V0.1 的产品形态即 CLI，命令即交互契约）：**

| 命令 | 行为定义 |
|---|---|
| `zhiying doctor` | 环境自检：依赖/版本/Key 配置/数据库连通逐项检查并给出修复提示（对齐仓颉 doctor 实践；新用户第一条命令） |
| `zhiying config` | 交互式引导配置模型 Key/默认模式/并发上限（未配 Key 时首次运行自动引导） |
| `zhiying ingest <url\|本地路径> [--mode=keyframe\|full\|agent]` | 创建处理任务并返回 task_id；默认 agent 智能选段；完成后自动产出 A1+A3；默认后台执行并即时返回 task_id（不等处理完成，用 status/watch 查进度） |
| `zhiying status [task_id]` | 无参列出全部任务与阶段状态；有参输出单任务详情（各阶段耗时/token） |
| `zhiying watch <task_id>` | 实时跟踪单个任务进度至完成/失败，结束行提示产物路径与下一步命令 |
| `zhiying retry <task_id>` | 仅重跑失败片段（FR-102），已完成产物不重建 |
| `zhiying open <task_id>` | 打开产物目录（multimodal_transcript.md） |
| `zhiying export <task_id> --format=xxx` | 触发制扩展：调用注册的导出器产出附加形态（md 文档/Skill/srt/Anki 卡片等，见 §5.4 A5/A6） |

**CLI 用户友好设计原则（DR-19）**：
- 零配置即可用：首次运行自动进入 `zhiying config` 交互式配置向导，未配置 Key 时所有消耗命令给出明确提示
- 长任务异步化：`ingest` 默认立即返回 task_id，不阻塞；用户用 `watch` 主动跟踪或 `status` 被动查
- 失败可恢复：任何任务 `retry` 只处理失败片段；产物目录结构固定，脚本/Agent 可程序化消费
- 命令自解释：每个子命令支持 `--help`，错误输入给出最接近的正确命令建议
- 成本透明：每个命令末尾提示「本次调用消耗 LongCat XXX token（约 X 元）」或「本次调用未产生 LLM 费用」

**V0.2 REST API 契约（以 OpenAPI 为准，路径草案）：**

| 端点 | 行为定义 |
|---|---|
| `POST /api/tasks` | 提交任务（source/mode）；同视频处理中或已完成返回 409 + 既有 task_id（FR-203 幂等） |
| `GET /api/tasks` · `GET /api/tasks/{id}` | 任务列表/详情；状态机 queued→downloading→transcribing→visual→summarizing→done/failed，含阶段进度与失败片段清单 |
| `DELETE /api/tasks/{id}` | 取消任务：终止当前片段，保留已完成产物 |
| `POST /api/search` | 检索（query, top_k 默认 5）→ 返回 chunks+时间戳引用 |
| `POST /api/ask` | 问答 → 返回 A4 结构化回答 |
| `POST /api/exports` | 触发制扩展：调用导出器（format/task_id），产物文件返回下载路径（见 §5.4 导出器扩展机制） |

交互约束：并发任务上限默认 2（可配）；VLM/LLM 调用属外部传输，提交页明示（§6 隐私）。

**V0.3 Web 交互流（页面 × 行为矩阵）：**

| 页面 | 关键交互 |
|---|---|
| 任务台 | 粘贴链接→提交→任务卡片实时阶段进度（SSE/轮询）→失败片段单点重试 |
| 知识库 | 视频列表（状态/时长/主题标签）→详情页分段浏览 A1 内容+原视频嵌入播放 |
| 问答 | 提问→流式回答+引用角标→点击引用→deep link 跳转原视频对应时间点（J3） |

**Web 用户友好设计（DR-19 同原则）**：
- 一键式新任务：粘贴链接即提交，复杂选项（视觉模式/并发）折叠为高级设置，默认推荐值
- 进度可见：任务卡片实时阶段进度+预估剩余（基于同长度视频历史耗时）；失败片段高亮可单点重试
- 零登录：单用户阶段无注册登录，开箱即用；回答界面明确展示引用来源与时间戳，无据可答时显式告知而非编造
- 成本可见：问答/处理页常驻 token 消耗徽标，配置页显示余额/预估

**Agent 工具接入（OpenClaw / Claude Code / Codex）**：统一以 MCP Server 方式接入，完整方案见 §5.6。

### 5.6 Agent 工具接入方案（OpenClaw / Claude Code / Codex）

**接入原则**：REST API（§5.5）是唯一契约底座；Agent 侧不直连数据库、不参与管道执行。所有 Agent 工具通过一层 **MCP（Model Context Protocol）Server** 接入——一次实现三端通用，不为每个 Agent 单独写胶水代码。

**MCP Server 形态**：

- 实现：Python 官方 MCP SDK 薄包装（单文件量级），stdio 传输运行，内部转发到本地 REST API（契约不二写，无第二套业务逻辑）
- 暴露 5 个工具：`zhiying_ingest(url, mode?)` / `zhiying_task_status(task_id?)` / `zhiying_search(query, top_k?)` / `zhiying_ask(question)`（返回 A4 结构化回答含引用）/ `zhiying_list_videos(topic?)`
- 返回结构化 JSON（任务状态机 / A4 引用含 deep link），Agent 可直接转述或渲染

**三端接入方式**：

| Agent 工具 | 接入方式 | 用户体验 |
|---|---|---|
| OpenClaw | MCP 客户端配置接入，工具进工具目录可发现 | 对话里丢链接→自动建任务；直接提问→带时间戳引用的回答，无需开网页 |
| Claude Code | `claude mcp add` 注册 stdio server | 会话中直接调用知映工具检索/提问 |
| Codex | config.toml 的 mcp_servers 配置 | 同上 |

**边界与演进**：

1. Agent 是客户端不是执行者：管道始终跑在知映服务内，Agent 不承担下载/转写/VLM 编排——与仓颉依赖编码 Agent 编排一切的模式划清界限
2. Claude Code / Codex 作为开发工具编写知映代码 ≠ 运行时接入，两者互不影响
3. 传输演进：单机部署默认 stdio；实例部署到无头服务器/远程访问时切 HTTP（可带鉴权），工具契约不变。多用户场景不存在共享实例（见 §5.7 仓颉同构模型），无需为多租户设计传输层

### 5.7 部署与资源模型

| 部署形态 | 适用阶段 | 部署内容 | 硬件要求 | 资源消耗方 |
|---|---|---|---|---|
| 本地单机自部署（唯一默认形态） | V0.1 起持续 | 每用户在自己机器跑全家桶：Python 管道 + PostgreSQL（本地容器/安装）+ FastAPI + 前端；自己的 Agent（OpenClaw/Claude Code/Codex）经 MCP 接入**自己的**实例 | 无 GPU 硬性要求：下载/转写（云 API）CPU 即可；本地 Whisper 或本地 VLM 才需要 GPU（可选） | **部署方=使用者本人**：VLM/LLM 调用走自己的 Key、自己付费；视频与知识数据全部落在本机 |
| 第二用户接入（开源分发模式） | 出现第二真实用户时 | 对方按部署文档自行部署**自己的**实例（同仓颉模式：装工具+配自己的 Key）；分发方式见 DR-15（Agent 辅助安装推荐 + 标准包路径），不提供共享实例 | 同上 | **每个部署方为自己的消耗付费**；项目作者不承担任何使用者的算力/模型成本 |
| 公有服务化（远期可选，触发制） | 仅在明确拍板 SaaS 化后另立版本规划评估 | 多租户、鉴权、配额、计费 | — | 平台方承担模型消耗并向使用者收费（该模式与仓颉模型不同构，默认不启动） |

**资源消耗归属原则（仓颉同构，DR-13 拍板）**：谁部署、谁的 Key、谁付费。每用户自部署自己的知映实例，VLM/LLM 消耗（分析视频/摘要/问答的 token）全部走部署者自己的 API Key（首选 LongCat-2.5，官方赠送 1000 万 token 活动覆盖起步；备选 Qwen-VL/GLM 系）；转发者（MCP/Agent 工具如 OpenClaw、Claude Code）只传指令不碰模型调用，不产生模型费用。**本项目任何形态下不存在「部署方为使用者代付模型消耗」的默认模式**——这是仓颉 12K Star 实证可行的零基础设施成本路线。

**数据与隐私边界**：视频源文件、转写、切片、向量、摘要全部存部署方本地/自托管存储；唯一外发=调用 VLM/LLM API 时的片段文本与帧图（属于 §6 已明示的外部传输）；知识库不随 Agent 工具共享——接入知映的 Agent 只能查询到部署方本机知识库。

## 6. 非功能需求

- **成本护栏**：单任务 token 消耗预估展示，提交前可确认；费用记录可审计。
- **合规边界**：只处理用户有权访问的内容，不绕过平台付费墙/DRM；平台授权（如视频号登录态）仅本地存储。
- **可恢复性**：所有中间产物落盘（下载缓存/转写/帧图/切片），任何阶段可断点续跑。
- **可插拔性**：转写引擎、VLM、文本 LLM（摘要/问答）、向量库、产物导出器均为适配器/注册制接口，不绑死单一供应商。
- **隐私**：视频与转写数据默认仅本地存储；VLM 调用属于外部传输，需在界面明示。

## 7. 明确不做（Non-Goals）

| 不做 | 理由 |
|---|---|
| 视频 AI 剪辑/创作/生成 | 定位是「消费侧知识提取」，不是创作工具 |
| 实时流（直播）分析 | 与收藏夹场景无关，复杂度指数级上升 |
| 自训/微调模型 | 纯应用层编排，成本与定位不符 |
| 移动端（V1 阶段） | 首发用户是桌面开发者，Web 优先 |
| 绕过平台风控的批量爬取 | 合规红线 |
| 多用户 SaaS 化（V1 阶段） | 先单机单用户验证价值，产品化另立版本 |
