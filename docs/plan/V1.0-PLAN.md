# 知映 zhiying — V1.0 实施计划（产品化）

> 状态：✅ 已完成（2026-11-10）
> 关联：`docs/PRD.md`（V1.0 触发条件：单机稳定使用 / 出现第二真实用户 / 知识库 ≥50 条视频）

## 1. 一句话定位

把 V0.3 的开发形态变成**可交付给他人使用的产品**：一条命令起全套、开箱即用的 Web 界面、三种 Agent 接入方式、完整部署文档。

## 2. 为什么现在做（触发条件达成）

| 条件 | 状态 |
|---|---|
| 单机稳定使用 | ✅ V0.1–V0.3 全链路真实验收通过 |
| 交付他人使用 | 触发本次产品化 |
| 需要低门槛接入 | 用户明确要求「使用最方便」「MCP 接入最简单」 |

## 3. 任务拆解与验收

| 任务 | 交付 | 验收 |
|---|---|---|
| P1 打包标准化 | `pyproject.toml`（依赖/console scripts/可选 whisper extra） | `pip install -e .` 生成 `zhiying`/`zhiying-api`/`zhiying-mcp` 三命令；`python -m build` 出 wheel |
| P2 镜像化 | `Dockerfile` 多阶段 + `PIP_INDEX_URL` 参数（国内源） | 真机构建成功 `zhiying/server:0.3.0`（1.13GB）；容器内 `version=0.3.0` + 三 CLI 就位 |
| P3 单容器全栈 | FastAPI 托管前端静态（`ZHIYING_WEB_DIST` + SPA 回退） | 容器根路径返回 index.html；`/library` 深链 200；静态资源 200 |
| P4 编排 | `docker-compose.yml`：server + postgres，数据卷持久化 | `docker compose config` 解析正确（端口 8600/15432，DB host 指向服务名） |
| P5 部署文档 | `docs/DEPLOY.md`：三条路径 + 初始化 + 备份 + 排错表 | 按文档可复现部署（A docker / B 本地 pip） |
| P6 MCP 接入最简化 | `docs/MCP-SETUP.md` + `scripts/zhiying-mcp.cmd` 启动器 | 四种 Agent 均一条配置即接入；容器内 5 工具注册验证 |
| P7 许可证与元数据 | `LICENSE`（MIT）+ `.dockerignore` | 与 README 声明一致 |

## 4. 实施记录

### P1 打包（2026-11-10）
- `pyproject.toml`：setuptools backend，src layout，依赖与 requirements 对齐，`whisper` 作为 optional extra
- 验收：editable 安装后三脚本生成，`zhiying doctor` 全绿；`python -m build` 产出 `zhiying-0.3.0-py3-none-any.whl`（56KB）

### P2 镜像（2026-11-10）
- 多阶段：builder 装依赖 → runtime 精简；非 root 运行；`ZHIYING_DATA=/data`
- **首次构建卡死**（国内网络 pip 无输出）→ 加清华源 + `--progress=plain` 后 46.8s 成功
- 镜像 1.13GB，含 console scripts

### P3 单容器全栈（2026-11-10）
- `api.py` 增加前端托管：`ZHIYING_WEB_DIST` 指向 dist，`/assets` 静态挂载 + catch-all SPA 回退（含目录穿越防护）
- 验收（容器实测 8701）：根路径 index.html、`/library` 200、CSS/JS/favicon 全 200

### P4 编排（2026-11-10）
- 两服务：`zhiying-server`（含 `depends_on: postgres healthy`）+ `zhiying-postgres`（pgvector/pg18）
  （原含 `zhiying-redis`，V1.3 已移除：代码零引用，仅注释提及「未来可换 Redis 队列」，属配置冗余）
- 关键修正：宿主机端口变量从 `ZHIYING_DB_PORT` 改为 `ZHIYING_DB_HOST_PORT`——前者是应用直连端口（本地=5432），复用会导致容器映射占本机 5432
- 数据卷：`zhiying-data` / `zhiying-pgdata`（原含 `zhiying-redisdata`，V1.3 随 redis 一并移除）

### P5/P6 文档（2026-11-10）
- `DEPLOY.md`：Docker 一键 / 本地直装 / 验证清单 / 排错表 / 第二用户自部署建议
- `MCP-SETUP.md`：四种 Agent 接入（Claude Code 一条命令 / Codex / OpenClaw / 通用 JSON）+ 5 工具话术示例
- `scripts/zhiying-mcp.cmd`：Windows 启动器（处理 venv 与 PYTHONPATH）

### 附带修复（真实缺陷）
1. `Dockerfile` 首版缺 `COPY src`（`pip install .` 必失败）→ 补源码 COPY
2. `doctor.py` 用 `getenv` 未导入（py_compile 查不出，实跑才炸）→ 补 `from zhiying.envkeys import getenv`
3. `__version__` 0.2.0 落后于 V0.3 → 0.3.0
4. `requirements` 缺 `opencv-python-headless`（frames.py 直接 import cv2）→ 补声明
5. compose 端口变量冲突（见 P4）

## 5. Non-Goals

- Kubernetes / 蓝绿发布（V1.0 只到 docker compose 单机；多机编排另立版本）
- 多租户 SaaS（DR-13：每用户自部署，不提供共享实例）
- 镜像推送公共 registry（用户各自 `docker compose build`）
- 前端镜像内构建（前后端分仓，前端产物只读挂载，保持两仓独立）

## 6. 决策记录

| 日期 | 决策 | 依据 |
|---|---|---|
| 2026-11-10（DR-29） | 单容器全栈：FastAPI 托管前端静态文件，不引入 nginx | 单用户单机场景，少一个组件少一处故障；nginx 仅在多实例/HTTPS 终止时才必要，可后续按需加 |
| 2026-11-10（DR-30） | Dockerfile 默认清华 PyPI 源（构建参数可覆盖） | 实测官方源构建卡死无输出；国内部署必须镜像源，海外可覆盖 |
| 2026-11-10（DR-31） | 前端产物只读挂载（`../zhiying-web/dist:/app/web:ro`），不 COPY 进镜像 | 保持两仓独立；前端改动只需 `npm run build` + `compose restart`，无需重建镜像 |
| 2026-11-10（DR-32） | MCP 接入以「启动器脚本 + 文档」交付，不打包成独立可执行 | 用户只用填一个 .cmd 路径；打包 pyinstaller 会引入 100MB+ 体积与杀软误报，收益不抵成本 |
