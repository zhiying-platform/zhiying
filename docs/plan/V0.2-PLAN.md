## 1. 一句话定位

把 V0.1 的单视频产物沉淀为**可持续增长的知识库**：PG+pgvector 入库、向量+全文混合检索、FastAPI 服务层、RAG 问答（A4 带时间戳引用）、MCP Agent 接入。

## 3. 实施记录

### S8 入库（kb.ingest_video）

- A1 JSONL 逐段 → segments；相邻段合并 → chunks（目标 ~600 字）
- embedding：BAAI/bge-m3 实测 **1024 维**（与 schema_v1 契约 `vector(1024)` 匹配；Qwen3-Embedding-8B 实测 4096 维不匹配弃用）
- tsv 全文：应用侧 jieba 分词 + `to_tsvector('simple')`；迁移 002 补列 + GIN 索引（正式迁移器 `zhiying.storage.migrate`）
- chunk 文本融合【口播+画面+屏幕文字】；实测教训：美食视频 SenseVoice 只有音乐符号噪声，纯口播 chunk 是空壳

### S10 检索（kb.search）

- 向量 cosine 为主 + tsvector 全文为辅（jieba），加权混合去重
- psycopg list → pgvector 类型坑：`%s::vector` + 文本字面量显式 cast 修复
- 实测：『菠萝怎么处理』命中处理片段 0.667；『屏幕文字』命中 OCR 内容

### S11 FastAPI + RAG（api.py / rag.py）

- 端点：health / tasks(幂等 409) / search / ask / videos；进程内队列线程执行
- ask：A4 结构化回答 + 引用强制溯源（无引用时兜底用检索 hit）；无据可答明确声明

### LongCat-2.5 激活（DR-14 落地，2026-11-10）

- 新 Key 激活后补齐 `describe_frame_longcat`（此前仅注册未实现）；base64 内联传图
- **关键发现：LongCat-2.5 是思考型模型**——`reasoning_tokens` 吃光 max_tokens 导致 content 为空；必须 `enable_thinking=false`（实测生效，content 117 字含双语 OCR）
- RAG 输出 JSON 被 max_tokens=800 截断（解析失败回退原文）→ 提至 2000
- 验收：视觉（双语 OCR）+ 文本 + 端到端问答 24s/4 条引用，全通过；性能对比 SiliconFlow 快约 4 倍

### Key 分离混搭模式（DR-20，2026-11-10 拍板）

- 视觉与文本 Key 支持分离配置：`ZHIYING_VLM_*_API_KEY` / `ZHIYING_TEXT_*_API_KEY` 优先于共享 Key
- 未配置专用 Key 时回落共享（当前都配 LongCat）；支持 LongCat 视觉 + SiliconFlow 文本等任意组合
- 验证：双链路（视觉/文本）各自优先级链实测通过

## 4. Non-Goals

- Redis 队列（进程内线程起步，FR-301 的 Redis 化随 V0.3 服务常驻一起做）
- A5 整理文档 / A6 Skill 备料包（DR-16 触发制，2026-11-10 拍板不提前）
- Web 前端（V0.3）

## 5. 决策记录

| 日期 | 决策 | 依据 |
